# 調査メモ：現実の政策会議・話し合いの種類と合意形成

本アプリの「会議の種類」「情報開示レベル」「合意ルール」「フェーズ」は、以下の現実の慣行をモデル化したもの。

## 1. 情報開示レベル（何をどこまで話せるか）

| レベル | 現実の例 | 発言への影響 |
|---|---|---|
| **公開・記録あり** (`public`) | 審議会（原則公開・議事録公表）、議会委員会、公聴会、ライブ配信 | 建前中心。支持者・有権者・株主・同僚に聞かれる前提。失言リスクを避け、組織の公式見解を述べる。数字や約束は慎重。 |
| **非公開・議事要旨のみ** (`closed`) | 「率直かつ自由な意見交換を確保するため原則非公開」とする研究会・検討会。議事要旨は発言者名なしで公表 | 公式見解＋その背景事情を語れる。「正直に言うと現場では…」が出る。 |
| **チャタムハウス・ルール** (`chatham`) | シンクタンクの円卓会議、国際会議の非公式セッション。内容は使ってよいが発言者を特定しない | 個人の本音・組織内の異論・不確かな見通しを話せる。 |
| **オフレコ・根回し** (`offrecord`) | 根回し、料亭/会食での非公式協議、閣僚間の事前調整、労使の事務折衝 | 本当の利害（予算、票、ポスト、業界の内情、譲れる線・譲れない線、代替案＝BATNA）を明かし、取引（パッケージディール）をする。記録は残さない（アプリ上はユーザーにだけ見える）。 |

日本の審議会運営規則では「原則公開、ただし座長判断で非公開」「非公開でも議事要旨は公表」が典型。開示レベルの判断を座長（進行役）に委ねる条項も多い。

## 2. 会議の種類（アプリで選べるもの）

| ID | 名称 | 開示 | 典型的な進め方 | 合意ルール | 成果物 |
|---|---|---|---|---|---|
| `council` | 審議会・有識者会議 | 公開 | 事務局が論点・たたき台を提示 → 委員が順に意見 → 論点整理 → 座長がとりまとめ案 → 修正 → 「座長一任」 | 座長一任／両論併記 | 答申・報告書（案） |
| `study_group` | 非公開の検討会・研究会 | 非公開 | 現状共有 → 率直な意見交換 → 選択肢の洗い出し → 方向性の確認 | ゆるいコンセンサス | 論点整理・方向性メモ |
| `hearing` | 公聴会・ヒアリング | 公開 | 各立場が順に意見陳述 → 質疑 → 意見の整理（決定はしない） | 決定なし（意見聴取） | 意見の整理表 |
| `town_meeting` | タウンミーティング・住民説明会 | 公開 | 行政/事業者が説明 → 住民の質疑・意見 → 回答 → 持ち帰り事項の確認 | 決定なし（持ち帰り） | 質疑応答記録・持ち帰り事項 |
| `citizens_assembly` | 市民会議・ミニパブリックス（討論型世論調査を含む） | 公開（討議は小グループ） | 学習（情報提供）→ 熟議 → 提言作成 → 投票。討論型世論調査では討議前後の意見変化を測る | 投票（提言ごとの支持率）＋事前事後比較 | 市民提言 |
| `roundtable` | マルチステークホルダー円卓会議（合意形成アプローチ） | チャタムハウス | 招集 → 利害の明確化（ポジションの奥にあるインタレスト）→ 選択肢の創出（相互利益）→ パッケージ化 → 「これなら受け入れられる」の確認 → 実施体制 | コンセンサス（全員が "live with" できる） | 合意文書（条件・実施体制付き） |
| `negotiation` | 交渉・折衝（労使交渉、予算折衝、政党間協議） | 非公開 | 要求提示 → 根拠の説明 → 争点の特定 → 譲歩と取引 → 妥結/決裂 | 当事者全員の合意（妥結） | 妥結内容・覚書 |
| `nemawashi` | 根回し・非公式協議 | オフレコ | 本音の共有 → 譲れる線・譲れない線の確認 → 取引 → 表の会議のシナリオ作り | 暗黙の了解 | 表の会議に向けた落とし所メモ |
| `assembly_committee` | 議会の委員会審議 | 公開 | 提案説明 → 質疑（質問者と答弁者）→ 討論（賛成/反対）→ 採決 | 多数決 | 可決/否決・附帯決議 |
| `cabinet` | 閣議・政策決定会議 | 非公開（決定は公表） | 案件説明 → 異論の有無確認 → 了承（実質は事前に調整済み） | 全会一致 | 決定事項 |

## 3. 合意形成ルール

| ID | 名称 | 判定方法 |
|---|---|---|
| `chair_discretion` | 座長一任 | 大筋の方向性で一致したら、細部の文言を座長に任せることを全員が了承する。異論は「意見」として残る |
| `both_views` | 両論併記 | 合意できない論点は、両方の意見を併記して報告する |
| `consensus` | コンセンサス | 全員が「積極的に賛成」または「受け入れられる（live with）」。拒否（ブロック）が1人でもいれば不成立。5段階の賛意（全面賛成〜拒否）で確認する |
| `majority` | 多数決 | 賛成過半数で可決。少数意見は附帯意見として残る |
| `unanimity` | 全会一致 | 全員賛成が必要 |
| `vote_ranked` | 提言ごとの投票 | 提言ごとに賛成率を出す（市民会議型） |
| `no_decision` | 決定しない | 意見を聴取・整理するだけ |

## 4. 交渉・合意形成の理論（エージェントの内部モデル）

- **ポジションとインタレスト**（ハーバード流交渉術）：表向きの要求（ポジション）の奥に本当の利害（インタレスト）がある。対立はたいていポジションのレベルで起き、インタレストのレベルでは両立できることがある。
- **BATNA**（交渉が決裂した場合の最善の代替案）：これより悪い合意はしない、という基準になる。
- **ZOPA**（合意可能領域）：各当事者の「受け入れられる範囲」が重なる部分。「落とし所」はここにある。
- **パッケージディール／ログローリング**：重要度の違う論点同士を交換する（Aは論点1を譲り、Bは論点2を譲る）。
- **合意形成アプローチ**（Susskindらの Consensus Building）：招集 → 責任の明確化 → 熟議 → 決定 → 実施の5段階。合意は「全員が満足」ではなく「全員が受け入れられる」こと。
- **熟議**：学習 → 熟議 → 決定の3段階。討論型世論調査は合意を目的とせず、意見の変化を測る。

## 5. 進行役・書記の役割（現実の慣行）

- 進行役（座長・議長・ファシリテーター）は、参加者のうち1人が兼ねることが多い（審議会の座長は委員の互選、議会の委員長は議員）。本来の立場を持ったまま、中立的に進行しようとする。それでも自分の立場がにじむことがあり、それ自体がリアルさになる。
- 書記・事務局は原則として発言しない。議事録（発言録）と議事要旨（要点）を作る。審議会では事務局（役所）が議事録を作り、発言者の確認を経て公表する。
